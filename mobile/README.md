# imkitchen mobile

Native Android/iOS app for the signed-in part of imkitchen (kitchen, cooking
mode, groceries, recipes, settings), built with
[Sparkling](https://tiktok.github.io/sparkling/) on top of
[Lynx](https://lynxjs.org/) (ReactLynx, TSX, native rendering).

The app is a pure client of the JSON API in `web/api` (`/api/v1/*`). It never
loads HTML from the server. Billing and upgrade flows deliberately do not exist
in the app (store payment policies); users subscribe on the website.

## Layout

| Path | What |
|---|---|
| `app.config.ts` | Rspeedy entries (one bundle per native container), package ids, splash, `__API_BASE_URL__` |
| `src/pages/<name>/` | One Lynx entry per screen container; `main` hosts the tab bar |
| `src/lib/api/` | Typed fetch client and per-area API modules |
| `src/lib/` | Config, auth store, navigation helpers, i18n, theme |
| `src/styles/tokens.css` | Design tokens mirrored from the web app's `tailwind.css` |
| `android/` | Android shell (`app.imkitchen.android`), Kotlin, Gradle 8.2 / AGP 7.4.2 |
| `ios/` | iOS shell generated by the template; **unverified** (no Mac in the dev environment) |

Template: `sparkling-app-template` 2.0.1 via `create-sparkling-app` 2.0.1
(`sparkling-app-cli` 2.0.1, Android SDK `com.tiktok.sparkling:sparkling:2.0.1`).
Sparkling is in public beta, so every JS dependency is pinned exactly; bump them
deliberately and re-run `npm run autolink` afterwards.

## Develop (Android)

Everything below runs inside the repo's `nix develop` shell, which provides
Node 24, JDK 11, the Android SDK (API 34), the emulator and `adb`.

```bash
# 1. API server on the host (port 3000)
cargo run -- --config config/dev.local.toml serve

# 2. Emulator (first time: create the AVD)
android-avd-create
android-emulator &

# 3. Build + install the debug app, start the dev server with HMR
cd mobile
npm install
npm run run:android
```

Every build talks to `http://10.0.2.2:3000`, the emulator's alias for the
host, unless `IMKITCHEN_API_URL` says otherwise. For a USB device use
`adb reverse tcp:3000 tcp:3000` and
`IMKITCHEN_API_URL=http://localhost:3000 npm run run:android`. Only
`npm run build:release` targets `https://imkitchen.app`.

Other commands:

```bash
npm run dev          # Rspeedy dev server only (port 5969)
npm run build        # bundles -> dist/ (dev API URL), copied into the native asset folders
npm run build:release # same, against https://imkitchen.app
npm run typecheck    # tsc --noEmit
npm test             # vitest
npm run doctor       # environment check (see note below)
cd android && ./gradlew assembleDebug   # debug APK without the CLI
```

## Screens (bundles)

| Bundle | Params | What |
|---|---|---|
| `main` | `tab?` | Tab shell: Kitchen, Groceries, Recipes, Settings |
| `login` | — | Sign in, password reset request |
| `cooking` | `id` | Cooking mode (ingredients, steps, timer, embedded origin page); keeps the screen on |
| `recipe` | `id` (id or slug) | Recipe detail: add to list, save, share, edit, delete, similar |
| `recipe-edit` | `id` | Editor: fields, dynamic ingredients/steps, photo upload |
| `recipe-import` | — | Paste a JSON array of up to 20 recipes |
| `cook` | `username` | A chef's public recipes |

Page parameters are read with `pageParams()` (`src/lib/nav.ts`), see the quirks.

### Known quirks

- `sparkling doctor` reports "Java is not installed" even though JDK 11 is on
  the PATH: it only reads `java -version` from stdout, while the JDK prints to
  stderr. Gradle builds work; ignore that line.
- The `--namespace` flag of `create-sparkling-app` 2.0.1 is ignored; the
  package was renamed by hand to `app.imkitchen.android` (Kotlin package,
  Gradle `namespace`/`applicationId`, manifest, `app.config.ts`, iOS bundle id).
- Lynx `fetch` has no cookie jar, does not follow redirects and has no
  `FormData`/`Blob`. The API is designed around that: Bearer token, JSON
  bodies, JSON 401s.
- Lynx `<input>` defaults to `maxlength=140`; always set it explicitly. The
  host provides the element itself (`LynxInputComponent.kt`): keep it
  uncontrolled (`TextField` passes the initial value only), echoing every
  keystroke back through `value` races the native cursor.
- Sparkling 2.0.1 (Android) never delivers custom scheme query params to the
  page: `lynx.__globalProps.queryItems` only holds `containerInitTime`. The
  host router (`SparklingHostRouterDepend.kt`) injects them as
  `__globalProps.pageQuery` through the container's `RuntimeInfo`.
- The bundled Lynx has no `<webview>` element on Android; the host registers
  one (`LynxWebViewComponent.kt`, a `WebView`).
- `sparkling-storage` declares `project(":sparkling-method")`; the shim module
  `android/sparkling-method` re-exports the Maven artifact. Keep it outside
  the autolink block of `settings.gradle.kts`.
- Every autolinked method package must also be registered in
  `SparklingApplication.kt` (`registerIDLMethod`); autolink only writes the
  registry file. `sparkling-media`'s `module.config.json` has no `android`
  section, so its registry entry is blank, but the Gradle project links.
- `sparkling-method-cli codegen` 2.0.1 emits broken TypeScript and Swift;
  `methods/keep-awake` keeps only its Kotlin abstract class and hand-writes
  the rest.
- Each bundle is its own JS runtime: nothing in memory survives a container
  push. The API client reloads the session from storage on first use.

## Release

Signing is manual for now: keep the keystore outside the repo and point Gradle
at it from `~/.gradle/gradle.properties`. Build with
`npm run build:release && (cd android && SPARKLING_USE_NATIVE_ASSETS=true ./gradlew assembleRelease)`.
